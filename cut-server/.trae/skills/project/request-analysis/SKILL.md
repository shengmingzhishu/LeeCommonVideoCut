# 需求分析与任务拆分

## 技能目标

当用户需要对后端需求做分析、澄清、技术方案设计或任务拆分时，使用本技能。

本技能的目标是基于用户需求和当前代码库的实际实现，产出结构化、可落地的需求分析文档与编码任务拆分文档，帮助后续 AI 编码或人工开发直接执行。

## 参考规范

本技能依赖当前目录下的规范文件完成不同类型需求的分析与拆分：

- `REFERENCE/新增类需求分析.md`：用于分析从 0 到 1 的新增功能类型需求。
- `REFERENCE/修改类需求分析.md`：用于分析从 1 到 N 的修改功能类型需求。
- 如后续补充任务拆分规范，应优先按对应拆分规范生成任务文档。

## 适用场景

- 用户提供 PRD、需求描述、流程说明，希望生成技术方案。
- 用户希望基于当前代码库分析需求入口、链路和改动点。
- 用户希望把需求分析结果继续拆分为可执行的编码任务。
- 用户尚未明确需求属于新增、修改或删除，需要先做需求归类。

## 输入要求

执行本技能时，优先收集以下信息：

- 需求背景与目标。
- 功能范围、边界和约束。
- 现有系统或模块名称。
- 相关 PRD、流程图、接口文档或示例数据。
- 代码仓库中可能相关的模块、入口或历史实现。

如果用户提供的信息不足以支持准确分析，需要明确列出待确认项，禁止编造业务规则或系统能力。

## 工作流程

### 1. 识别需求类型

根据用户需求判断本次需求属于：

- 新增：从 0 到 1 增加全新能力或新业务场景。
- 修改：在现有能力基础上调整逻辑、流程、规则或兼容行为。
- 删除：下线、废弃或收缩已有能力。

若无法直接判断，先输出分类依据和待确认问题，再继续分析。

### 2. 创建需求变更目录

在当前项目根目录下按以下规则组织产物：

1. 若不存在 `.changes` 目录，则创建 `.changes`。
2. 在 `.changes` 下创建本次需求的子目录，命名格式为 `${变更类型}-${需求名称}-${当前日期}`。
3. 示例：`新增-订单功能-20240601`。

### 3. 生成需求分析文档

根据需求类型选择对应规范：

- 新增需求：使用 `REFERENCE/新增类需求分析.md`。
- 修改需求：使用 `REFERENCE/修改类需求分析.md`。

生成的需求分析文档保存到对应变更子目录下，命名格式为 `需求分析-${需求名称}.md`。

### 4. 分析代码与方案

执行需求分析时，必须遵循以下原则：

- 从用户需求涉及的入口代码开始分析完整链路。
- 先识别已有实现、公共能力和可复用模块，再判断新增或改动点。
- 输出内容必须基于真实代码和明确需求，不能凭空补充不存在的逻辑。
- 对不确定内容使用“待决议列表”记录，留给人工确认。

## 输出要求

输出结果至少包括以下内容：

- 需求类型判断结果。
- 需求分析文档摘要。
- 关键代码链路和主要改动点摘要。
- 编码任务拆分摘要。
- 待确认问题或风险提示。

如果已经生成文档，还应明确说明文档保存位置。

## 执行约束

- 严格依据用户输入和代码库分析结果输出内容。
- 优先复用现有能力，避免凭空设计重复接口和数据结构。
- 所有分析都要兼顾兼容性、可维护性和可测试性。
- 对新增能力要关注数据模型、接口协议、监控告警、权限和异常处理。
- 对修改能力要关注回归风险、兼容行为和已有流程影响。

## 推荐输出格式

建议按以下顺序给出结果：

1. 需求类型与判断依据。
2. 需求分析结论。
3. 代码链路与核心模块分析。
4. 技术方案摘要。
5. 任务拆分摘要。
6. 风险与待确认事项。

## 非目标

- 不在缺少关键信息时虚构实现细节。
- 不跳过代码分析直接输出泛化方案。
- 不把与本次需求无关的大范围重构作为默认方案。
