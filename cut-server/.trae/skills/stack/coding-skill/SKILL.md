# Python 编码 Skill

> **定位**：通用 Python 编码工具。适用于编写独立函数、脚本、工具类、数据处理逻辑等**非 FastAPI 特有**的代码。
>
> **与 fastapi-python 的区别**：
> - `coding-skill` = 通用 Python 代码（函数、类、脚本、数据处理、算法）
> - `fastapi-python` = FastAPI 项目专用（路由定义、依赖注入、Pydantic Schema、中间件、lifespan）
>
> **选择建议**：写纯 Python 逻辑用 coding-skill；写 API 接口/路由/请求处理用 fastapi-python。

## 技能说明

这是一个简单示例版的 Python 编码 skill。

当需要快速编写 Python 代码、生成基础后端逻辑、补充简单接口或输出示例实现时，可以使用本技能。

本技能强调：代码简单、结构清楚、容易继续修改。

## 编码原则

- 优先保证代码正确，再考虑扩展性。
- 代码尽量简单，不引入不必要的复杂设计。
- 命名清晰，函数职责单一。
- 只修改当前需求相关内容，不扩散到无关模块。
- 能复用已有代码时，优先复用已有实现。

## Python 编码要求

- 优先使用清晰直接的写法。
- 函数要有明确输入和输出。
- 需要时补充基础类型标注。
- 做好必要的参数校验。
- 异常处理尽量明确，不随意吞异常。
- 不输出敏感信息到日志。

## 后端代码建议

如果是在后端场景下编写代码，优先关注：

- Controller 只做参数接收、基础校验和结果返回。
- 业务逻辑尽量放在 service 层。
- 不要把复杂逻辑全部堆在接口函数里。
- 返回结构尽量统一。

## 工作方式

编写代码时，建议按以下步骤执行：

1. 先理解需求，明确输入、输出和边界条件。
2. 找到最接近的现有代码风格或相似实现。
3. 用最小改动完成目标功能。
4. 检查是否有明显的异常路径和边界问题。
5. 输出结果时说明改动点和需要关注的风险。

## 输出要求

输出代码时尽量满足以下要求：

- 直接给出可落地的实现。
- 不写空泛说明。
- 如果有前提假设，需要明确说明。
- 如果暂时没有完整上下文，优先给最小可行版本。

## 示例

下面是一个简单的 Python 示例：

```python
def add(a: int, b: int) -> int:
    if a is None or b is None:
        raise ValueError("a 和 b 不能为空")
    return a + b
```

## 非目标

- 不主动做大规模重构。
- 不为了“高级感”加入复杂设计模式。
- 不把简单问题过度抽象。
