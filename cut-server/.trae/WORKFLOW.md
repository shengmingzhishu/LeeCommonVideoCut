# Skills 工作流编排指南

> 本文档描述 ai-server 项目中多个 Skill 的组合使用方式。
> 根据任务类型选择合适的工作流，按顺序执行各步骤。

## 工作流 1：新功能开发流

**适用场景**：新增完整的业务功能模块（如 M10 智能笔记、M11 Bug 管理）

```
┌──────────┐    ┌──────────────────┐    ┌─────────────┐    ┌──────────┐
│ qa-reset  │──▶│ request-analysis │──▶│ task-spliter│──▶│ design-  │
│ (需求澄清) │    │ (需求分析+方案)  │    │ (任务拆分)  │    │ doc-code-│
└──────────┘    └──────────────────┘    └─────────────┘    │completion│
                                                           └────┬─────┘
                                                                │
                                ┌─────────────┐    ┌────────────▼────────┐
                                │ python-     │◀───│ code-review        │
                                │ testing     │    │ (代码审查)          │
                                └─────────────┘    └─────────────────────┘
```

**执行要点**：

1. **qa-reset**：如果需求表述不清，先用此 skill 结构化需求
2. **request-analysis**：产出 `.changes/需求分析-${名称}.md`
3. **task-spliter**：产出 `.changes/任务拆分-${名称}.md`
4. **design-doc-code-completion**：按任务逐步实现，每步跑单测
5. **python-testing**：全量测试
6. **code-review**：产出 `.changes/review/代码检查-${名称}-${日期}.md`

**产物清单**：

```
.changes/
└── ${变更类型}-${需求名称}-${日期}/
    ├── 需求分析-${需求名称}.md
    ├── 任务拆分-${需求名称}.md
    └── review/
        └── 代码检查-${需求名称}-${日期}.md
```

## 工作流 2：Bug 修复流

**适用场景**：修复已知缺陷、回归问题

```
┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ coding-skill │──▶│ python-     │──▶│ code-   │
│ 或           │    │ testing     │    │ review  │
│ fastapi-     │    └─────────────┘    └──────────┘
│ python       │
└──────────────┘
```

**执行要点**：

1. **coding-skill / fastapi-python**：定位问题并修复（优先选 fastapi-python 如果涉及 API 层）
2. **python-testing**：运行受影响的测试，确保修复有效且无回归
3. **code-review**：轻量审查（聚焦修复点，不扩大范围）

**简化规则**：
- 不需要 request-analysis（Bug 已有明确描述）
- 不需要 task-spliter（修复范围通常清晰）
- code-review 只检查修复引入的新风险

## 工作流 3：新评测方向扩展流

**适用场景**：新增评测方向（如代码评审、多模态评测）

```
┌─────────────────────┐    ┌─────────────────────┐    ┌─────────────┐
│ eval-direction-     │──▶│ eval-direction-     │──▶│ python-     │
│ extension (分析设计) │    │ extension (编码实现) │    │ testing     │
└─────────────────────┘    └─────────────────────┘    └──────┬──────┘
                                                              │
                                                       ┌──────▼──────┐
                                                       │ code-review  │
                                                       └─────────────┘
```

**执行要点**：

1. **eval-direction-extension**（第 1 遍）：只读 SKILL.md 了解步骤，不做编码
2. **eval-direction-extension**（第 2 遍）：按步骤依次实现 Evaluator → Scorer → 配置注册 → Schema
3. **python-testing**：重点测试新方向的正常/异常路径
4. **code-review**：检查是否符合四层架构、是否正确继承基类

**配合使用**：
- 如果新方向需要新被测系统，先执行 **工作流 4**
- 如果需要设计评测用例，配合 **工作流 5**

## 工作流 4：新被测系统接入流

**适用场景**：接入新的 LLM 提供商、RAG 系统、MCP Server

```
┌──────────────────────┐    ┌──────────────────────┐    ┌─────────────┐
│ target-system-       │──▶│ target-system-       │──▶│ python-     │
│ integration (分析)   │    │ integration (实现)   │    │ testing     │
└──────────────────────┘    └──────────────────────┘    └──────┬──────┘
                                                               │
                                                        ┌──────▼──────┐
                                                        │ code-review  │
                                                        └─────────────┘
```

**执行要点**：

1. **target-system-integration**（第 1 遍）：填写「目标系统分析」表格
2. **target-system-integration**（第 2 遍）：按步骤实现 Schema → Client → Manager → Entity
3. **python-testing**：重点测试连接、认证、重试、超时
4. **code-review**：检查安全性（密钥处理）、错误处理完整性

## 工作流 5：评测用例设计流

**适用场景**：为新方向设计用例、补充回归集

```
┌─────────────────┐    ┌─────────────────┐
│ eval-case-      │──▶│ 手动/脚本验证    │
│ design          │    │ 用例可执行性    │
└─────────────────┘    └─────────────────┘
```

**执行要点**：

1. **eval-case-design**：按方向选择模板，设计用例集
2. **手动验证**：抽样 3-5 条用例，确认输入/预期/评分规则合理
3. **批量导入**：通过文件导入接口批量加载

**最佳实践**：
- 先设计 easy 级别用例，验证流程通畅后再补充 medium/hard
- 每个方向至少 20 条用例才能得到有统计意义的评分
- 定期（每月）回顾用例，移除过时用例

## 快速选择指南

| 你的任务是... | 使用工作流 |
|---------------|-----------|
| "帮我实现 XXX 功能" | **工作流 1**：新功能开发流 |
| "这个 Bug 怎么修" | **工作流 2**：Bug 修复流 |
| "新增一个 XX 评测方向" | **工作流 3**：新评测方向扩展流 |
| "接入 XX 模型/服务" | **工作流 4**：新被测系统接入流 |
| "帮我设计 XX 方向的用例" | **工作流 5**：评测用例设计流 |
| "需求不太清楚，帮我梳理" | 先用 **qa-reset**，再进入对应工作流 |
