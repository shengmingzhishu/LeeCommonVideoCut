# 项目概述

> 本文档是 ai-server 项目的定制规则，仅适用于本项目。

## 项目名称

ai-server（AI 测评系统）

## 项目目标

构建一个高性能、可配置、可扩展的 AI 测评系统，支持：
- 通过配置接入不同的被测系统，完成不同方向的测试
- 多测试方向：文本问答、SQL 脚本正确性测试、RAG 评分测试等
- 多测试方式：AI 模型测试、RAG 评分测试等
- 多数据接入方式：文件导入、页面接口添加
- 用户登录与权限管理
- 历史测试记录管理与复测
- 测试集管理：勾选历史测试内容重新测试或反复测试
- 多维度评分与报告生成

## 技术栈

| 类别 | 技术选型 | 说明 |
|------|---------|------|
| 编程语言 | Python 3.13+ | 遵循项目要求 |
| Web 框架 | FastAPI + Uvicorn | 异步高性能 API 服务，端口 8000 |
| 大模型接入 | OpenAI SDK / MCP | 模型调用与工具调用评测 |
| 数据库 | SQLAlchemy + MySQL | 数据持久化（192.168.182.72:31306/db_ai_eval） |
| 任务调度 | asyncio + APScheduler | 异步批量执行 + 定时触发 |
| 认证 | JWT Token | 用户登录与接口鉴权 |
| 测试框架 | pytest | 单元测试与集成测试 |

> 注：暂不使用 Redis，互斥锁用数据库行锁/内存锁，任务队列用 asyncio 原生。后续如有性能需要再加回。

## 项目范围

### 核心功能

1. **多方向评测**
   - 文本问答评测：对话能力、推理能力、知识准确性
   - SQL 脚本正确性测试：SQL 生成与执行结果验证
   - RAG 评分测试：检索增强生成质量评估
   - 支持通过配置扩展新的评测方向

2. **多测试方式**
   - AI 模型测试：直接调用 LLM 进行能力评测
   - RAG 评分测试：评估 RAG 系统的检索和生成质量
   - 支持通过配置切换测试方式

3. **被测系统接入**
   - 通过配置接入不同的被测系统（LLM 服务、RAG 系统、MCP 工具服务器等）
   - 配置驱动的系统选择，无需修改代码即可切换

4. **测试数据管理**
   - 文件导入：支持批量导入测试用例（Excel/JSON/CSV）
   - 页面接口添加：通过 API 单条或批量添加测试用例
   - 测试集管理：创建、编辑、删除测试集

5. **用户管理**
   - 用户注册与登录（JWT Token 鉴权）
   - 接口权限控制
   - 用户数据隔离

6. **历史记录与复测**
   - 历史测试记录查询与管理
   - 勾选历史测试内容重新测试
   - 已测试内容反复测试
   - 测试结果对比与趋势分析

7. **评测报告**
   - 多维度评分与统计
   - 报告生成与导出
   - 评测结果可视化

### 非功能需求
- **性能**：支持高并发评测请求，任务队列解耦
- **可扩展性**：支持新增评测方向、测试方式、被测系统，无需大范围修改代码
- **可靠性**：任务失败重试，结果可追溯
- **安全性**：用户认证，接口鉴权，评测数据隔离

## 关键约束

1. **评测可复现**：相同输入在相同配置下应得到可复现的评测结果
2. **配置驱动**：评测方向、测试方式、被测系统均通过配置切换，非代码硬编码
3. **模型可插拔**：评测引擎支持多种 LLM/MCP/RAG 后端切换
4. **异步处理**：大批量评测采用异步任务模式，不阻塞请求
5. **结果可追溯**：所有评测请求、响应、评分明细均需记录日志，支持事务 ID 链路追踪
6. **数据隔离**：不同用户的测试数据相互隔离，历史记录独立管理

## 架构层级

项目采用四层架构（详见 `common/02-architecture-patterns.md`）：

- **Controller 层**：路由、参数校验、鉴权、响应封装
- **Service 层**：单领域业务逻辑（评测用例管理、任务管理、用户管理）
- **Manager 层**：跨领域编排（评测流程编排、外部系统接入适配、多策略路由）
- **Model 层**：数据模型、数据库访问、外部接口封装
