# video-cut · 跨端协作约定

> **本文档是 cut-server 与 cut-web 之间协作的唯一铁律。**
> 任何接口/字段/路径/错误码变更必须先改本文档 + `cut-server/docs/04-接口契约.md`，再改两侧代码。
> 违反本约定的 PR 应直接打回。

---

## 0. 阅读对象与时机

- **什么时候必须读**：写任何 API 调用代码、写任何后端 Controller、写任何前端 Service 之前。
- **不读的后果**：前后端字段名不一致 → 调试 2 小时；错误码前端漏处理 → 用户看到 500；traceId 缺失 → 联查失败。

## 1. 接口契约权威

### 1.1 唯一权威文档

| 内容 | 权威文件 |
|------|---------|
| 接口路径 / 方法 / 请求体 / 响应体 | [cut-server/docs/04-接口契约.md](../cut-server/docs/04-接口契约.md) |
| 字段 snake_case ↔ camelCase 映射 | `cut-server/docs/04-接口契约.md` 附录 A |
| 错误码分级（40xxx/41xxx/50xxx/60xxx） | [§4 本文档](#4-错误码体系) |
| 跨端协作铁律（本文档） | 本文件 |

### 1.2 变更流程（强制）

任何对接口的修改必须按以下顺序：

```
1. 改 cut-server/docs/04-接口契约.md（先改契约）
2. 改后端 Pydantic schema + Controller + Service + Manager
3. 改前端 src/types/api/ + Service + Hook
4. 跑前后端联调验证
5. 在 cut-server/docs/04-接口契约.md §10 变更记录 追加一行
6. 提交 PR，PR 描述里贴出契约变更 diff
```

**禁止**：
- ❌ 先改代码、后补契约（事后追补容易遗漏）
- ❌ 只改一侧代码（必然产生不一致）
- ❌ 改契约但不写变更记录（后人无法追溯）

### 1.3 契约版本兼容策略

- **新增字段**：前端可选处理，后端必须支持
- **删除字段**：必须先标记 deprecated（保留 1 个版本），下个大版本删除
- **修改字段类型/语义**：视为破坏性变更，必须在契约文档中标注 `⚠️ BREAKING`
- **修改路径/方法名**：必须新建接口 + 旧接口保留过渡期（不少于 1 个发布版本）

## 2. 字段命名

### 2.1 响应 JSON 字段一律 camelCase

```json
// ✅ 正确（后端用 Pydantic alias_generator=to_camel）
{
  "code": 0,
  "msg": "ok",
  "data": {
    "projectId": "uuid",
    "videoDir": "C:\\videos\\demo",
    "currentStep": 3,
    "createdAt": "2026-09-03T10:00:00+08:00"
  }
}
```

```json
// ❌ 错误（snake_case 不允许出现在响应中）
{
  "code": 0,
  "data": {
    "project_id": "uuid",
    "video_dir": "C:\\videos\\demo"
  }
}
```

### 2.2 请求体字段：snake_case 或 camelCase 二选一

**video-cut 当前决策**：请求体统一使用 **camelCase**（与响应一致，减少映射代码）。

```json
// ✅ 正确
POST /api/step2/analyze
{
  "projectId": "uuid",
  "searchEnabled": true,
  "searchCount": 3
}
```

后端 Pydantic 配置：

```python
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel

class Step2AnalyzeRequest(BaseModel):
    model_config = ConfigDict(
        alias_generator=to_camel,
        populate_by_name=True,  # 允许两种命名
    )
    project_id: str
    search_enabled: bool = True
    search_count: int = 1
```

### 2.3 内部 Python 代码

- 后端内部：snake_case（Python 惯例）
- 前端内部：camelCase（JS/TS 惯例）
- 数据库表字段：snake_case（SQL 惯例）
- **响应/请求 JSON**：camelCase（见 §2.1）

### 2.4 字段映射表维护

- **位置**：`cut-server/docs/04-接口契约.md` 附录 A
- **更新时机**：任何字段重命名/类型变更时
- **自动化**（未来）：用 `openapi-typescript` 从 FastAPI OpenAPI 自动生成前端类型，附录 A 退化为"只在新字段未自动生成时手填"

## 3. traceId 链路追踪

### 3.1 格式与传递

- **格式**：UUID v4 字符串（例：`7a8b9c0d-1e2f-3a4b-5c6d-7e8f9a0b1c2d`）
- **请求头**：`X-Trace-Id`（前端 axios 拦截器自动注入）
- **后端获取**：FastAPI 中间件从 `request.headers.get("X-Trace-Id")` 读取
- **后端响应**：写入响应头 `X-Trace-Id`（便于前端确认）
- **后端日志**：每条日志必带 `[tx:{traceId}]` 前缀

### 3.2 前端职责

- 每次请求**必带** `X-Trace-Id`（axios 拦截器统一处理）
- 收到 4xx/5xx 响应时，**自动把 traceId 写入错误日志**（`utils/logger.ts`）
- 用户报错时**显示** traceId（toast / 弹窗内），便于联查

```typescript
// services/request.ts（前端）
axios.interceptors.request.use((config) => {
  config.headers['X-Trace-Id'] = config.headers['X-Trace-Id'] 
    || generateTraceId()  // utils/request.ts
  return config;
});

axios.interceptors.response.use(
  (response) => {
    const traceId = response.headers['x-trace-id'];
    if (traceId) response.data.traceId = traceId;
    return response;
  },
  (error) => {
    const traceId = error.response?.headers?.['x-trace-id'];
    logger.error(`[${traceId}] ${error.config.url} failed:`, error);
    return Promise.reject(error);
  }
);
```

### 3.3 后端职责

```python
# utils/logs.py（后端示例）
from loguru import logger
import contextvars

tx_id_var: contextvars.ContextVar[str] = contextvars.ContextVar('tx_id', default='no-tx')

class TraceIdMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        tx_id = request.headers.get('X-Trace-Id') or str(uuid.uuid4())
        token = tx_id_var.set(tx_id)
        with logger.contextualize(tx=tx_id):
            response = await call_next(request)
        response.headers['X-Trace-Id'] = tx_id
        tx_id_var.reset(token)
        return response

# 使用
logger.info(f"Project {project_id} created, user={user_id}")
# 输出：2026-09-03 10:00:00 | INFO | [tx:7a8b9c0d...] | projects_service | create | 45 | Project xxx created
```

### 3.4 联查流程

1. 用户报错，截图包含 traceId
2. 开发者用 traceId grep 后端日志：`grep "tx:7a8b9c0d" logs/*.log`
3. 找到该请求的完整链路（中间件 → Controller → Service → Manager → 外部 API）
4. 定位失败点

## 4. 错误码体系

### 4.1 统一响应格式

```json
{
  "code": 0,
  "msg": "ok",
  "data": { ... }
}
```

- HTTP 状态码固定 200
- 业务错误放在 `code` 字段
- 成功 `code=0`，失败 `code != 0`

### 4.2 错误码分级

| 范围 | 含义 | 触发条件 | 前端处理 |
|------|------|---------|---------|
| **0** | 成功 | 正常返回 | 正常处理 data |
| **40001** | 参数缺失 / 校验失败 | 缺字段、字段格式错、长度超限 | 弹 toast 显示 msg，不重试 |
| **40101** | 项目不存在 | project_id 无效 | 跳回项目列表 |
| **40102** | 步骤锁定 | 前置步骤未完成 | 弹 toast + 高亮提示"请先完成 StepN" |
| **40103** | 素材资源不存在 | 视频文件被删/移走 | 弹 toast + 引导重新选目录 |
| **40104** | 任务不存在 | task_id 无效 | 跳回任务列表 |
| **40105** | 历史版本不存在 | history_id 无效 | 跳回历史列表 |
| **50001** | AI 调用失败 | DeepSeek / OpenAI 超时或返回错误 | 弹 toast + 显示 traceId + 重试按钮 |
| **50002** | 搜索失败 | Bing / DuckDuckGo 失败 | 弹 toast + 提示切备用引擎 |
| **50003** | TTS 失败 | edge-tts / pyttsx3 失败 | 弹 toast + 提示切兜底引擎 |
| **50004** | ffmpeg/ffprobe 失败 | 系统 ffmpeg 不在 PATH / 切片失败 | 弹 toast + 提示检查 ffmpeg 安装 |
| **50005** | IO 错误 | 磁盘满 / 文件被占用 | 弹 toast + 提示检查磁盘 |
| **50006** | 内部异常兜底 | 未捕获的 Python 异常 | 弹 toast + 提示提交反馈（带 traceId） |
| **60001** | 长任务失败 | 音频合成 / 裁切 / 合成任务失败 | 任务详情页显示错误 + 重试按钮 |
| **60002** | 长任务已取消 | 用户主动取消 | 任务详情页切到 cancelled 态 |
| **60003** | 长任务超时 | 任务执行超过 N 分钟 | 任务详情页切到 failed + 提示 |

### 4.3 前端错误处理映射

```typescript
// utils/errors.ts
const ERROR_HANDLERS: Record<number, (msg: string, traceId?: string) => void> = {
  0: () => {},  // 成功，不需要
  40001: (msg) => message.warning(msg),
  40101: (msg) => { message.error('项目不存在'); navigate('/projects'); },
  40102: (msg) => message.warning(`请先完成前置步骤：${msg}`),
  50001: (msg, traceId) => message.error(`AI 调用失败 [${traceId}]，请重试`),
  50004: (msg) => message.error('ffmpeg 不可用，请检查系统安装'),
  60001: (msg, traceId) => message.error(`任务失败 [${traceId}]，请重试`),
  // ...
};

axios.interceptors.response.use(
  (response) => response.data,
  (error) => {
    const data = error.response?.data;
    if (data?.code != null) {
      const handler = ERROR_HANDLERS[data.code] || ((msg) => message.error(msg));
      handler(data.msg, data.traceId);
    }
    return Promise.reject(error);
  }
);
```

### 4.4 新增错误码流程

1. 在 `cut-server/docs/04-接口契约.md §0.3` 表格追加一行
2. 后端抛出对应异常（Pydantic + 业务异常类）
3. 前端 `ERROR_HANDLERS` 加一行处理函数
4. 跑一次联调验证

## 5. CORS 与鉴权

### 5.1 CORS

| 环境 | 前端地址 | 后端 CORS 白名单 |
|------|---------|-----------------|
| 开发 | `http://localhost:5173` | `["http://localhost:5173"]` |
| 生产 | 由部署决定 | 由 `vc_config.corsOrigins` 动态配置 |

**规则**：
- 禁止 `allow_origins=["*"]`（除非是纯公开 API）
- 开发期后端必须接受 `http://localhost:5173`，否则 Vite 代理失效
- 生产部署时 `vc_config.corsOrigins` 必须显式列出允许的域名

### 5.2 鉴权（本期默认放行）

- 视频剪辑师本期定位是**本地工具**，鉴权默认关闭
- `vc_config.auth_enabled=false` 时，所有接口**不需要 Token**
- `vc_config.auth_enabled=true` 时，所有业务接口必须校验 `Authorization: Bearer <token>`
- 前端在登录页或设置页提供"启用鉴权"开关，写入 `vc_config`

**预留**：
- 前端 axios 请求拦截器在 `authEnabled=true` 时注入 `Authorization`
- 后端中间件在 `auth_enabled=true` 时校验 JWT
- 即使本期不启用，前端仍保留 `useAuthStore` 和登录页骨架

## 6. 长任务约定

### 6.1 短任务 vs 长任务

| 类型 | 判定 | 响应 |
|------|------|------|
| 短任务 | < 3s | 同步返回完整结果 |
| 长任务 | ≥ 3s | 返回 `{taskId}`，前端轮询 `/api/task/{taskId}` |

video-cut 的长任务：音频合成（Step4）、视频裁切（Step6）、音视频合成（Step7）

### 6.2 任务状态

```typescript
type TaskStatus = 'pending' | 'running' | 'success' | 'failed' | 'cancelled';
```

### 6.3 前端轮询约定

- 任务详情页进入时**立即**查一次状态
- `running` 状态每 5s 轮询
- 终态（`success` / `failed` / `cancelled`）**立即停止轮询**
- 组件卸载时**必须取消轮询**（`useEffect` cleanup），避免内存泄漏
- 轮询请求需带 AbortController，组件卸载时 `controller.abort()`

### 6.4 取消语义

- 用户点击"取消"→ 前端乐观更新 `task.status='cancelled'`
- 取消请求发出后**不能**立即标记 cancelled，**必须等待后端 ack**
- 取消时若后端正在写历史，**必须等待后端 ack** 后再提示用户"已取消"
- 取消按钮置灰条件：任务已 `success / failed / cancelled` 时不可点

## 7. 时间与 ID 格式

### 7.1 时间

- **格式**：ISO 8601 字符串带时区（`2026-09-03T10:00:00+08:00`）
- 后端 Pydantic：`datetime` 字段，自动序列化 ISO 8601
- 前端 TS：`string`，解析时用 `new Date()` 或 dayjs

### 7.2 ID

| 实体 | 格式 | 示例 |
|------|------|------|
| 项目 ID | UUID v4 字符串 | `"7a8b9c0d-1e2f-3a4b-5c6d-7e8f9a0b1c2d"` |
| 历史版本 ID | UUID v4 字符串 | 同上 |
| 任务 ID | `{prefix}_{uuid_short}` | `audio_a1b2c3d4` / `mark_x9y8z7w6` / `cut_m5n6o7p8` / `compose_q1r2s3t4` |

任务 ID 前缀固定，便于日志搜索：
- `audio_`：Step4 音频合成
- `mark_`：Step4 视频标记
- `cut_`：Step6 裁切合并
- `compose_`：Step7 合成 + 字幕

## 8. 文件与目录约定

### 8.1 前端 TypeScript 类型

- 统一放在 `cut-web/src/types/api/`，**与 `04-接口契约.md` 一一对应**
- 文件命名：`{domain}.types.ts`（如 `project.types.ts`、`step4.types.ts`）
- 每个接口的请求/响应**单独 type**，便于复用
- **禁止**在 `components/` 或 `pages/` 下散落定义接口类型

### 8.2 后端 Pydantic Schema

- 统一放在 `cut-server/src/ai_eval_server/models/schemas/`
- 文件命名：`{domain}.py`（如 `project.py`、`step4.py`）
- 必须 `model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True)`

### 8.3 数据库字段

- snake_case（SQL 惯例）
- 必备字段：`id`（UUID 主键）、`created_at`、`updated_at`
- 软删除字段：`deleted_at`（可空，删除时写入当前时间）
