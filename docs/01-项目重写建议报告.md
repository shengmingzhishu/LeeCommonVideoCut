## 五、风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 旧版 TTS/AI Key 配置丢失 | 重写后用户需重新配置 | 提供"导入旧数据库"工具（一键迁移） |

| 虚拟预览器交互复杂 | 实现偏差 | 直接复用旧版 CSS 变量与布局，单元测试覆盖关键交互 |
| AI 输出质量下降 | 业务效果降低 | 保留旧 prompt 模板（提取到 `services/prompts/`） |
| 项目进度中断 | 旧项目状态无法续接 | 导出/导入项目快照（JSON 序列化全部 state） |
| 大文件（视频）IO 慢 | 体验差 | 流式上传/下载 + 进度条 |

## 六、关键原则总结

1. **契约先行**：阶段 1 必须先把 OpenAPI 写清楚，前后端都按契约开发
2. **可回滚**：每阶段产出物独立可演示，单阶段失败不影响整体
3. **零复刻死代码**：旧 HTML 中无效的兼容性代码、调试代码不迁入新版
4. **视觉 1:1**：参考旧 `static/index.html` 的 CSS 变量与布局，不要"设计升级"
5. **接口对齐**：旧 `API接口文档.md` + `前后端对接适配文档.md` 是接口设计的真值来源
6. **规则驱动**：阶段 2~6 全程使用 `karpathy-guidelines`，遵循"先思考、再写、精准修改"
7. **质量门禁**：每个阶段结束必须跑通 `09-cross-end-workflow.md` §质量门禁清单
