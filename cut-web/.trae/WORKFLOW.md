## 工作流 1：新功能开发流

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐
│ qa-reset  │──▶│ api-contract │──▶│ frontend-   │──▶│ frontend-│
│ (需求澄清) │    │ (拉取API契约) │    │ design      │    │ code-    │
└──────────┘    └──────────────┘    │ /model-     │    │ review   │
                                    │ design      │    └────┬─────┘
                                    └──────────────┘         │
                                                ┌───────────▼──────────┐
                                                │ a11y-audit            │
                                                │ (可访问性检查)         │
                                                └──────────────────────┘
```

**执行要点**：
1. **qa-reset**：如果需求表述不清，先用此 skill 结构化需求
2. **api-contract**：拉取后端 OpenAPI 契约，生成 TS 类型
3. **frontend-design / model-design**：实现页面/组件
4. **frontend-code-review**：审查代码质量
5. **a11y-audit**：检查可访问性

## 快速选择指南

| 你的任务是... | 使用工作流 |
|---------------|-----------|
| "帮我实现 XXX 页面" | **工作流 1**：新功能开发流 |
| "这个 Bug 怎么修" | **工作流 2**：Bug 修复流 |
| "帮我设计一个页面" | **工作流 3**：UI 设计流 |
| "页面太慢了" | **工作流 4**：性能优化流 |
| "前后端接口对齐" | **工作流 5**：前后端联调流 |
| "需求不太清楚" | 先用 **qa-reset**，再进入对应工作流 |
