## 1. 项目基本信息

- **项目名称**：video-cut（前端）
- **项目描述**（一句话说明做什么）：video-cut 项目的浏览器端 UI，承担 7 步向导、虚拟串播预览、项目/历史版本管理、全局配置等交互。
- **项目目标**：
  - 提供 7 步引导式创作流程，对应后端 7 个步骤接口
  - 实现"虚拟串播预览"核心体验（用 `<video>.currentTime` 模拟串播，0 IO）
  - 多项目卡片管理、历史版本对比/回滚可视化
  - 与 `cut-server`（FastAPI）通过 `{code, msg, data}` 统一格式交互

- **请求库**：axios + 自封装 `core/request.ts`（统一 traceId、错误处理）
- **长任务轮询**：自封装 `useTaskPoll` hook

- **代码检查**：ESLint（airbnb 风格）+ Prettier
- **测试**：

## 4. 业务领域

- **核心功能**（按页面/feature 划分）：
  1. **项目列表页（首页）**：项目卡片网格 + 新建/打开/复制/删除 + 状态筛选 + 搜索
  2. **Step1 输入信息面板**：标题/作者/简介/素材目录表单 + 素材扫描结果展示
  3. **Step2 拆解 + 搜索面板**：4 个关键词标签云 + 搜索关键词输入 + 文章列表采纳/弃用
  4. **Step3 口播文案面板**：左大纲（折叠）+ 右文案编辑器（富文本）+ 字数/时长预估
  5. **Step4 双线并行面板**：音频线（播放器+进度）+ 视频标记线（素材清单+标记预览）
  6. **Step5 虚拟预览面板**：【核心】 `<video>` 串播 + 标记列表编辑（起止/删除/拖拽/添加/随机重标）+ 时长匹配检查
  7. **Step6 裁切合并面板**：裁切参数 + 进度条 + 实时日志（可折叠）
  8. **Step7 合成 + 字幕面板**：合成参数 + 进度
  9. **完成页**：成品预览 + 创作总结 + 导出 PRD 包
  10. **全局配置面板**（⚙）：API Key、TTS 引擎/语音、搜索引擎、模型选择等
  11. **生成历史查看**：每步弹出版本列表、预览、对比、恢复
- **业务约束**：
  - 步骤锁定：前一步未完成，后一步骤置灰
  - 可回退 + 重新执行
  - 虚拟预览 0 IO（仅用 `<video>.currentTime` seek）
  - 不在 UI 内做剪辑逻辑，只调后端接口 + 渲染状态
  - 类型与后端 Pydantic schema 对齐，统一在 `src/types/api/` 维护
- **数据模型提示**（详见 `01-project-specific.md` §1.4）：
  - `Project`, `ProjectCreate`, `ProjectUpdate`
  - `KeywordAnalysis`, `Article`
  - `ScriptResult`, `AudioResult`, `TimestampSegment`
  - `VideoMarker`, `MarkerSet`, `CutResult`, `FinalResult`
  - `GenerationHistory`, `TaskStatus`
  - 步骤枚举：`STEP_INPUT=1` ~ `STEP_COMPOSE=7`

## 附录：与旧参考代码的差异要点

1. **不再用单文件 HTML**：旧参考 `static/index.html` 是内嵌 CSS + 原生 JS 的单文件，新项目用 React 组件化 + Vite 多页/单页均可（按 feature 拆）。
2. **不再挂静态资源**：旧参考 FastAPI 同时挂 `static/`，新项目前端独立 dev server，CORS 互通即可。
3. **去掉 episodes / creations 双层**：旧参考"项目 → 剧集 → 创作"三层，新项目扁平化为"项目 = 创作"。
4. **删除旧参考 `linked_episodes` 兼容字段**：新项目字段命名与后端 Pydantic 严格一致，无历史包袱。
5. **Ant Design 5 主题定制**：深色科技风通过 ConfigProvider + token 自定义，不依赖旧参考内联 CSS。
6. **不要 `dangerouslySetInnerHTML`**：旧参考部分文案用 innerHTML 注入，新项目用 React 受控渲染（按 [01-coding-standards.md §6](../../.trae/rules/web/common/01-coding-standards.md)）。
